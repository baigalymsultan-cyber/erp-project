## 5. Kaspi Pay API — NOT_FOUND (публичный developer API) / PARTIALLY_VERIFIED (смежный протокол)

- **Публичного официального developer API для приёма платежей Kaspi Pay (мерчант) не найдено.** Поиск по официальным источникам не дал документации для разработчиков по созданию платежей, статусам, возвратам через Kaspi Pay.
- **VERIFIED, но другая сущность:** официальный «Протокол взаимодействия АО "KaspiBank" с Компаниями поставщиками услуг» (check/pay: `command=check|pay`, `txn_id`, `txn_date`, `account`, `sum`, коды ошибок 0–5, идемпотентность по `txn_id`, QR-формат `https://kaspi.kz/pay/{serviceName}?...`). Это протокол сервиса **«Платежи на Kaspi.kz»** для компаний-поставщиков услуг (ЖКХ и т.п.), НЕ Kaspi Pay для мерчантов. Источник: https://guide.kaspi.kz/cdn/content/pay/product/documents/Instrukciya-po-integracii-1C-s-servisom-Platezhi-na-Kaspi-kz-dlya-distribyutorov.pdf
- **Наводка (НЕ официальный источник, НЕ контракт):** утёкший PDF старого протокола с `returnApi/Refund/RefundRequest` (`PaymentId`, `ReturnAmount`, `RefundIdentificatior`, `Reason`) — https://habrastorage.org/getpro/freelansim/allfiles/14/142/142179/Kaspi.pdf. Использовать как контракт запрещено.

## 6. Refunds/returns via API — NOT_FOUND (официальный API)

- **Seller API:** только `CANCELLED` + `cancellationReason` и `POST /v2/orderEntryCancelOperation` (частичная отмена) — VERIFIED в Part 1. Отдельного API возвратов нет.
- **Процедура возвратов (официально):** покупатель оформляет заявку на возврат в приложении Kaspi.kz («Магазин на Kaspi.kz → Мои заказы → Заявки на возврат»); срок определяет продавец. Источник: https://guide.kaspi.kz/client/ru/shop/returns/general/q16178 — Обновлен 15.09.2026.
- **Договор (п. 4.1–4.4):** «Возврат денег Покупателю за Товар осуществляется по поручению Партнера в Банк согласно заключенным договорам между Партнером и Банком.» Комиссия за обработку данных возвращается при возврате товара (кроме случаев нарушений партнёра); комиссия Kaspi Доставки не возвращается.
- **Правила работы с Магазином:** п. 4.6 запрещает «удерживать комиссию или просить деньги у покупателя при возврате». Источник: https://guide.kaspi.kz/cdn/content/pay/product/documents/Magazin/Pravila-raboty-s-Magazinom-na-Kaspi-kz.pdf
- **Вывод:** возвраты — через кабинет/поручения банку, не через публичный API.

## 7. Transaction identifiers — PARTIALLY_VERIFIED

**VERIFIED (официальный протокол check/pay, «Платежи на Kaspi.kz»):**
- `txn_id` — уникальный идентификатор платежа в системе Kaspi.kz, целое число до 18 знаков; используется для сверки и спорных вопросов; дубли `txn_id` запрещены (идемпотентность: «провайдер должен вернуть результат обработки предыдущего запроса»).
- `prv_txn` — уникальный номер оплаты в базе провайдера, до 20 знаков (возвращается после `pay`).
- `txn_date` — дата учёта платежа, формат ГГГГММДДЧЧММСС.
- `account` — идентификатор абонента/заказа в системе провайдера (до 200 символов).
- Коды ошибок: 0 (найден), 1 (не найден), 2 (заказ отменён), 3 (заказ уже оплачен), 4 (платёж в обработке), 5 (другая ошибка провайдера).
- Источник: https://guide.kaspi.kz/cdn/content/pay/product/documents/Instrukciya-po-integracii-1C-s-servisom-Platezhi-na-Kaspi-kz-dlya-distribyutorov.pdf

**VERIFIED (Seller API, Part 1):** `id` / `code` заказа, `waybill`, `waybillNumber`.

**NOT_FOUND:** официальная связка «заказ → платёж → выплата» (какой ID линкует заказ Seller API к выплате на счёт). В документации такой маппинг не описан.

## 8. Settlement timing (сроки перечисления) — VERIFIED

- **Магазин на Kaspi.kz:** «не позднее следующего рабочего дня после дня Оплаты Товара» (Договор, п. 3.4). Контроль: 3 рабочих дня → обращение в Kaspi (п. 3.7). Источник: https://guide.kaspi.kz/cdn/content/pay//product/documents/Dogovor-s-Kaspi-Magazinom.pdf
- **Kaspi Pay:** «Деньги за продажи поступают на Счет Kaspi Pay онлайн после каждой принятой оплаты за вычетом комиссии.» Источник: https://guide.kaspi.kz/partner/ru/red/returns/q369 — Обновлен 13.03.2025.

## Выводы для KASPI_OQ_003

1. **Новое по сравнению с Part 1:** официально задокументирован протокол `check/pay` («Платежи на Kaspi.kz») — даёт контракт идентификаторов (`txn_id`, `prv_txn`, `txn_date`), кодов ошибок (0–5) и требования идемпотентности. Но это канал для поставщиков услуг, не для мерчантов Kaspi Pay / продавцов маркетплейса — напрямую в OQ-003 не переносится.
2. **Тарифы комиссий** официально опубликованы (маркетплейс 2026, Kredit/Red+/QR/Доставка) — для расчётных моделей ERP их можно использовать как справочник, но программного доступа к ним нет.
3. **Процедуры выплат и сверки** официально описаны (сроки, акты, сверка до 7-го) — интеграция ERP остаётся «ручная выгрузка из кабинета + договорные процедуры».
4. **Программного API не существует официально** для: выплат, комиссий, сверки, возвратов, детальной платёжной информации, Kaspi Pay мерчант-платежей. Это технический блокер, закрываемый только реальным аккаунтом продавца + письменными уточнениями у поддержки Kaspi.
5. Ничего не выдумано: все endpoints/поля выше — либо из официальных документов с URL, либо явно помечены NOT_FOUND.
